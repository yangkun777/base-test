# 本机部署（同事通过局域网访问）

这台电脑跑 Node，Nginx 监听 80 端口并转发到本机 `127.0.0.1:3100`。同事用浏览器打开 `http://这台电脑的局域网IP/`，不需要单独装 Node。

API Key 只留在这台电脑的 `.env` 里。同事在页面上发起评测，会使用这台电脑的 Key，并产生模型费用。只给办公室内网使用，不要把 80 端口映射到公网。

## 第一次准备

1. 安装 Node.js。
2. 在项目根目录复制 `.env.example` 为 `.env`，填入 GPT 和 Gemini 的 Key。
3. 构建前端：

```powershell
cd frontend
npm install
npm run build
cd ..
```

国内网络可以加 `--registry=https://registry.npmmirror.com`。

## 启动

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-lan.ps1
```

脚本会做这些事：

- 3100 没有服务时，后台启动 `node server.js`，日志在 `data/server-lan.out.log` 和 `data/server-lan.err.log`。
- 第一次运行时下载 Nginx 1.28.0 到 `deploy/nginx/`（这个目录不提交）。
- 用 `deploy/nginx.conf` 启动或重载 Nginx。
- 尝试放行 Windows 防火墙的 80 端口。如果提示没加上，用管理员 PowerShell 再运行一次启动脚本。

启动后终端会打印地址：

- 本机：`http://127.0.0.1/`
- 同事：`http://192.168.x.x/`（以脚本打印的地址为准）

本机调试仍可直接打开 `http://127.0.0.1:3100`。

## 停止

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\stop-lan.ps1
```

这只停 Nginx。连本项目的 Node 一起停：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\stop-lan.ps1 -IncludeNode
```

## 改完代码之后

- 改了 `frontend/`：在 `frontend` 目录重新 `npm run build`，再刷新页面。
- 改了 `server.js` 或 `lib/`：先 `stop-lan.ps1 -IncludeNode`，再运行 `start-lan.ps1`。
- 只改了 `deploy/nginx.conf`：再运行一次 `start-lan.ps1`，脚本会重载 Nginx。

## 同事打不开时

1. 启动脚本的电脑和同事要在同一局域网。
2. 本机浏览器先打开 `http://127.0.0.1/`，确认页面能出来。
3. 防火墙规则需要管理员权限。管理员 PowerShell 里也可以手动执行：

```powershell
netsh advfirewall firewall add rule name="Degson GEO LAN 80" dir=in action=allow protocol=TCP localport=80
```

4. 80 端口被别的程序占用时，先停掉占用程序，再运行启动脚本。查看占用：

```powershell
Get-NetTCPConnection -LocalPort 80 -State Listen
```

5. Nginx 报错看 `deploy/nginx/logs/error.log`。Node 报错看 `data/server-lan.err.log`。
